# Shopkeeper Brain 工业化学习与改造会话包

这套文件把长期改造拆成一个总控会话和 17 个执行会话。每个执行会话只负责一个可验收能力，避免把调研、架构、编码和排障混在同一个超长上下文中。

## 现在怎么开始

保留当前对话作为“总控会话”，用于决定阶段、检查证据和调整路线。新建第一个执行会话后，发送：

> 请先读取 `docs/roadmap/MASTER_PLAN.md`、`docs/roadmap/CURRENT_STAGE.md`、`docs/roadmap/HANDOFF_TEMPLATE.md` 和 `docs/roadmap/sessions/00-quality-baseline.md`，然后直接执行该阶段。不要只给建议；完成代码、验证和交接记录。

阶段完成后，把执行会话输出的交接记录带回总控会话。总控会话确认验收门槛后，更新 `CURRENT_STAGE.md`，再开启下一阶段会话。

## 文件说明

- `MASTER_PLAN.md`：唯一的总路线、依赖关系和阶段门槛。
- `CURRENT_STAGE.md`：当前正在做什么、为什么做、何时算完成。
- `HANDOFF_TEMPLATE.md`：每个执行会话统一的交接格式。
- `sessions/*.md`：各阶段独立的启动说明、参考项目、任务和验收条件。

## 会话纪律

1. 一个执行会话只完成一个阶段；`04A`、`04B`、`04C` 分开。
2. 每个会话先读仓库和前序交接，再读参考项目的真实代码、测试、文档和 CI。
3. 参考项目是设计样本，不整仓照搬，也不因 Stars 高就默认适合本项目。
4. 每个阶段必须留下可运行代码、必要测试、指标或评测结果、设计决策和回滚办法。
5. 发现路线假设错误时记录证据并回到总控会话调整，不在执行会话中偷偷扩张范围。
